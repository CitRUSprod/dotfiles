---
description: Обновляет заголовок и описание открытого PR, если они расходятся с фактическими изменениями (коммитами и diff).
---

Команда не создаёт коммиты. Никогда не выполняй `git commit` и `git add`.

1. **Проверь окружение:**
    - Проверь, доступен ли `gh` CLI (`gh --version`). Если недоступен — сообщи об ошибке и прекрати выполнение.
    - Проверь авторизацию `gh` (`gh auth status`). Если не авторизован — сообщи об ошибке и предложи выполнить `gh auth login`, затем прекрати выполнение.

2. **Определи PR:**
    - Проанализируй `$ARGUMENTS` (если передан и не пуст):
        - Если это число (только цифры) — используй как номер PR (`pr_number`).
        - Если это URL вида `https://github.com/.../pull/N` — извлеки номер PR.
        - Если в тексте упоминается номер PR или URL — извлеки их.
        - Иначе — если не удалось извлечь PR, определи PR для текущей ветки.
    - Если PR ещё не определён — получи для текущей ветки: `gh pr view --json number,url,headRefName,baseRefName,title,body`
    - Из результата извлеки: `pr_number`, `pr_url`, `head_ref` (ветка PR), `base_ref` (базовая ветка), текущие `current_title` и `current_body`.
    - Если PR не найден или команда завершилась ошибкой — сообщи пользователю и прекрати выполнение.

3. **Собери данные для анализа:**
    - Получи коммиты PR:
        ```
        gh pr view <pr_number> --json commits --jq '.commits[].messageHeadline'
        ```
    - Если коммитов нет или команда завершилась ошибкой — сообщи пользователю и прекрати выполнение.
    - Получи diff PR:
        ```
        gh pr diff <pr_number>
        ```
        Если команда завершилась ошибкой — сообщи пользователю текст ошибки и прекрати выполнение.
    - Очисти diff от бинарных файлов: разбей diff на блоки по строкам, начинающимся с `diff --git`. Для каждого блока (от `diff --git` до следующего `diff --git` или конца файла) проверь, содержит ли он строку, целиком совпадающую с шаблоном `Binary files ... differ` (регулярное выражение `^Binary files .* differ$`) или строку `GIT binary patch` (регулярное выражение `^GIT binary patch$`). Если содержит — удали весь блок целиком.

4. **Определи язык заголовка и тела:**
    - В первую очередь посмотри текущие `current_title` и `current_body` PR — сохрани их язык.
    - Если по ним язык определить нельзя — посмотри несколько последних PR:
        ```
        gh pr list --state merged --limit 10 --json title,body
        ```
    - Если по ним тоже нельзя определить язык — уточни у пользователя, на каком языке писать заголовок и тело PR.

5. **Сгенерируй новый заголовок и тело PR:**
    - Проанализируй все коммиты (`gh pr view <pr_number> --json commits`) и содержимое очищенного diff.
    - Сгенерируй заголовок и тело заново целиком, отражая все текущие изменения PR.
    - Если пользователь передал аргументы (`$ARGUMENTS`), учти их как дополнительные указания при генерации (но не используй как готовый заголовок).
    - Язык заголовка и тела — язык, определённый на шаге 4.

6. **Сравни с текущими значениями:**
    - Сравни сгенерированный заголовок с `current_title` и сгенерированное тело с `current_body`.
    - Если заголовок и тело совпадают с текущими — сообщи: "Заголовок и описание PR уже актуальны, обновление не требуется" и прекрати выполнение.

7. **Если сессия только для чтения (plan mode):** просто выведи текущий и предложенный заголовок и тело PR без внесения изменений.

8. **Если сессия позволяет выполнять команды (build mode):** примени обновление:
    - Запиши сгенерированное тело во временный файл:
        ```
        BODY_FILE="$(mktemp "${TMPDIR:-/tmp}/opencode-prupdate-XXXXXX")"
        cat <<'PR_BODY_EOF' > "$BODY_FILE"
        <сгенерированное тело — без shell-экранирования>
        PR_BODY_EOF
        ```
    - Выполни:
        ```
        if gh pr edit <pr_number> --title "<заголовок>" --body-file "$BODY_FILE"; then
            rm -f "$BODY_FILE"
        else
            echo "Ошибка обновления. Новое тело сохранено в $BODY_FILE"
        fi
        ```
    - Сообщи пользователю ссылку на обновлённый PR (`pr_url`) и кратко перечисли, что изменилось в заголовке и теле.
